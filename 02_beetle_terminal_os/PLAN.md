# VT100 Terminal & Minimal OS Plan (`02_beetle_terminal_os`)

**Target hardware:** DFRobot Beetle ESP32-C6 (512 KB SRAM, 4 MB flash) or Beetle ESP32-C3 (400 KB SRAM, 4 MB flash); both single-core RISC-V at 160 MHz, 25.0 × 20.5 mm.  
**Goal:** A wireless-keyboard VT100 terminal with a local shell, flash storage, Telnet, an SSH-2 client, and a CP/M environment.

**Build status:** Both Arduino sketches compile for the Beetle ESP32-C6 and ESP32-C3 with `arduino-esp32` 3.3.12, `NimBLE-Arduino` 2.5.2, and `LibSSH-ESP32` 5.10.0 (`tools/compile_sketch.sh`). Both require the **"Huge APP (3 MB No OTA / 1 MB SPIFFS)"** partition scheme (images are 1.4–1.6 MB). The RP2350 HDMI display card builds to a UF2 image with the Pico SDK. Hardware testing is still pending.

---

## 1. Memory Budget

The Arduino core exposes **320 KB of DRAM** to the application on both the C6 (512 KB SRAM) and the C3 (400 KB); the remainder is used by instruction RAM, cache, and ROM data. Sizes below are measured from the compiled builds (`arduino-esp32` 3.3.12):

| Firmware | Flash Image | Static RAM | Heap Free Before Radios |
| :--- | ---: | ---: | ---: |
| Option A shell (C6 / C3) | 1.57 / 1.43 MB | 50 / 45 KB | 277 / 283 KB |
| Option B CP/M-style shell (C6 2 banks / C3 1 bank) | 1.58 / 1.43 MB | 149 / 127 KB | 179 / 200 KB |
| Project 1 BLE bridge (C6 / C3) | 1.43 / 1.27 MB | 51 / 46 KB | 276 / 282 KB |

Runtime heap usage on top of static RAM is roughly 70 KB for Wi-Fi + lwIP, 40 KB for NimBLE, and 55 KB for an active SSH-2 session. Option B therefore allocates 64 KB of base memory plus two 16 KB banks on the C6 (one 16 KB bank on the C3) so sufficient heap remains for SSH.

## 2. Video Output Options

### Option 1 (Recommended): RP2350-Zero HDMI VT100 Card (`VIDEO_BACKEND_UART_RP2350_HDMI`)
The Beetle sends ANSI/VT100 output over `UART1` (`TX`/`RX` from the board variant: GPIO 16/17 on C6, GPIO 21/20 on C3) at 921600 8N1. The RP2350-Zero runs [`video_backends/rp2350_hdmi_vt100_card.c`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/video_backends/rp2350_hdmi_vt100_card.c), an 80×30 16-color ANSI terminal rendered scanline-by-scanline in the HSTX DMA interrupt (`common/hstx_dvi.c`, 8×16 cells from `common/font8x8_basic.h`, UART drained by interrupt into a 4 KB ring buffer).
- Compiles to a 12 KB UF2 image for `waveshare_rp2350_zero`.
- Wiring: Beetle `TX` → RP2350-Zero `GPIO 1` (`UART0 RX`), `5V`, and `GND`; HDMI pins as in Project 1 (Pico DVI Sock order, Type D pin numbers).
- Offloads all video generation from the Beetle, and its `TermCell` grid is also used by Project 5's screen reader.

### Option 2: FabGL VGA (`VIDEO_BACKEND_VGA_FABGL`)
Works only on the classic dual-core Xtensa ESP32 with `arduino-esp32` 2.0.x. The classic Beetle ESP32 (`DFR0575`, 35 × 34 mm) is too large for an AirTag shell and only breaks out a subset of GPIOs, so this backend is only applicable to larger desk builds on standard ESP32 boards.

### Option 3: 2-Resistor Composite (`VIDEO_BACKEND_COMPOSITE_SPI`, Non-Working Stub)
Bit-banging composite scanlines from a 64 µs timer ISR on a single-core C3/C6 starves the BLE and Wi-Fi stacks; a working composite implementation would require a continuous full-frame DMA stream. [`video_composite_spi.h`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/video_backends/video_composite_spi.h) is kept only as a reference stub that refuses to compile unless `COMPOSITE_EXPERIMENTAL` is defined.

## 3. OS Option A: FreeRTOS Micro-Shell ([`beetle_rtos_ssh_terminal.ino`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/os_freertos_shell/beetle_rtos_ssh_terminal.ino))

Provides a local shell (`airtag:~$`) backed by LittleFS with:
- `wifi scan | wifi join <ssid> <pass> | wifi status`
- `ssh <user>@<host> [port]` (`LibSSH-ESP32`, requests a `vt100` 80×25 PTY)
- `telnet <host> [port]` (`Ctrl+]` exits)
- `ls`, `cat`, `rm`, `ed` (line editor)
- `ble`, `free`, `clear`, `reboot`

BLE keyboard input uses `NimBLE-Arduino` 2.x (bonding, boot and report notifications), translating HID reports to ASCII/VT100 sequences with `Ctrl`, `Shift`, arrow keys, `Home`/`End`/`Delete`/`PgUp`/`PgDn`, and key auto-repeat (400 ms delay, 30 Hz rate).

**Current limitation:** The SSH client does not yet verify the server's host key.

## 4. OS Option B: CP/M-Style Host Shell ([`beetle_cpm22_ssh.ino`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/os_cpm22_runcpm/beetle_cpm22_ssh.ino)) & RunCPM Patch

Provides an `A>` command processor with built-in `DIR`, `TYPE`, `ERA`, `PIP`, and `CLS`, drive `A:` on LittleFS (`/A0`), a RAM disk on `B:`/`M:` in the expanded memory pool, a 16 KB bank window at `0x8000` selected via `OUT (0F0h), A` or `BANK n`, and four transient utilities (`SSH.COM`, `TELNET.COM`, `WIFI.COM`, `BANK.COM`) generated by [`make_cpm_tools.py`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/os_cpm22_runcpm/make_cpm_tools.py) (verified under `z80pack` `cpmsim`). Those utilities trap into the ESP32 host via BDOS functions 220–223 with `DE` pointing to the command tail.

`beetle_cpm22_ssh.ino` itself only interprets the eleven Z80 opcodes used by those four `.COM` utilities. To run full Z80 CP/M 2.2 software (WordStar, Turbo Pascal, MBASIC, etc.), [`runcpm_patch/`](file:///home/ccd/retro_pc_project/02_beetle_terminal_os/os_cpm22_runcpm/runcpm_patch/README.md) provides a patch and header adding BDOS 220–224 to [RunCPM](https://github.com/MockbaTheBorg/RunCPM), verified on RunCPM's Linux build. Completing the Beetle RunCPM port requires adding a LittleFS filesystem abstraction header alongside the four BDOS handlers from `beetle_cpm22_ssh.ino`.

Note that CP/M's CCP upper-cases command tails: `SSH` converts `user@host` to lower case automatically, while Wi-Fi SSIDs containing lower-case letters should be joined once from Option A (credentials are stored in shared NVS).
